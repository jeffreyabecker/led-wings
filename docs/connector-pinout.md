# Connector Pinout — Wiring Legend (Pigtails)

> The shared signal interface for every strip chunk and covert row in this one-off build.
> Terminated as **2-pin JST-PNI pigtails** (2.0 mm, wire-to-wire — **both ends crimped, no
> headers**; parts + procedure: [pigtail-crimping.md](pigtail-crimping.md)). The wire-pair
> maps and colors below are the canonical build legend; every termination follows them.

## Topology

- **Data daisy-chains** chunk-to-chunk: the controller drives one `DI`/`CI` pair into the
  first chunk of a chain; each chunk's `DO`/`CO` feeds the next chunk's `DI`/`CI`. The last
  chunk's `DO`/`CO` is unused (end of chain).
- **Covert rows** are one continuous strip each: `PWR` + `DI`/`CI` at the row head, `DO`/`CO`
  at the tail feeding the next row's head.
- **Power fans out** from hub clusters: each chunk/row gets `+5V`/`GND` over a short 2-wire
  run from a nearby power-hub.
- **Connector scheme:** every chunk end is a **receptacle** (`PNIRR-02VF`) — power-in,
  data-in, data-out; all jumpers and feeds are **plugs** (`PNIRP-02V-S`). Both genders crimp
  (wire-to-wire, no soldered headers).
- Power and data use **separate wire pairs**.

## Signals

| Signal | Meaning |
|--------|---------|
| GND | Power ground (also the data signal return path) |
| +5V (VCC) | LED power (from power-hub) |
| DI | Serial data in (from controller, or previous chunk's `DO`) |
| CI | Serial clock in (from controller, or previous chunk's `CO`) |
| DO | Serial data out (regenerated by last LED, to next chunk) |
| CO | Serial clock out (regenerated by last LED, to next chunk) |

## Wire colors

| Signal | Wire color |
|--------|------------|
| +5V (VCC) | Red |
| GND | Black |
| DI / DO (data) | Yellow |
| CI / CO (clock) | Green |

Only **four colors** are used: red/black (power) and yellow/green (data vs clock). Data-in and
data-out cables reuse the same yellow/green pair — the connector function (data-in vs data-out
receptacle) sets the role, not the wire color.

## Wire-pair maps (canonical)

**Power — 2-wire (hub → chunk)**

| Wire | Signal |
|------|--------|
| 1 | GND |
| 2 | +5V (VCC) |

**Data IN — 2-wire (controller / previous chunk → this chunk)**

| Wire | Signal |
|------|--------|
| 1 | DI |
| 2 | CI |

**Data OUT — 2-wire (this chunk → next chunk)**

| Wire | Signal |
|------|--------|
| 1 | DO |
| 2 | CO |

## Wiring rules

- **Chunk-to-chunk data:** chunk N's `DO`/`CO` pads → chunk N+1's `DI`/`CI` pads, straight
  1:1. `DO` at the source becomes `DI` at the sink; the roles cross at the pads, not in the
  wire.
- **Controller → first chunk:** 5 V-logic `DI`/`CI` (Pixelblaze + 74AHCT125 level shifter)
  into the first chunk's `DI`/`CI`. Add a series R (33–100 Ω) at the chain head if the bench
  shows ringing.
- **Power:** 2-wire (red/black) from the hub to each chunk.
- **GND** lives only on the power pair. The data pairs are 2-wire (`DI`/`CI`, `DO`/`CO`) with
  no dedicated return — return current flows through the shared power `GND`. Hops are short
  regenerated SPI, so the extra loop area is negligible.
- **Strip pad layout:** cut chunks expose `+5V`/`GND`/`DI`/`CI` on the input end and
  `+5V`/`GND`/`DO`/`CO` on the output end — feed power at the input end so all six wires
  leave the chunk from one side.
- **Wire gauge:** power **20–22 AWG** silicone; data **24 AWG**. Keep any single run ≤
  ~2–3 A (PNI class rating — wiring plan). Signal current is negligible.
- **Strain relief:** glue/epoxy over every soldered pad set; never leave bare strip pads at a
  flex point.

## Rationale

- Power and data are split so power can scale independently (add a hub where a cluster needs
  it) while the data chain stays thin and short.
- A daisy chain needs no `DO`/`CO` return to a hub — the last chunk's `DO`/`CO` is simply
  unused.
- One data wire + one clock wire per hop keeps the harness minimal; the clocked SK9822
  protocol tolerates hop-to-hop runs better than single-wire NRZ.
- Data is **2-wire** with no `GND` pin: `GND` is already shared via the power pair, and each
  LED re-buffers the signals, so the return path through power `GND` is a non-issue at these
  short runs and clock rates.
